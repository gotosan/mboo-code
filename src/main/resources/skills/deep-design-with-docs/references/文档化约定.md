# 文档化约定

本资源只在深度设计确实需要判断、建议或写入术语表、上下文映射或 ADR 时读取。核心原则是：**仓库已有约定优先，下面的结构只作为没有既有约定时的 fallback。**

## 发现顺序

写入前按以下顺序确定真实文档位置和格式：

1. 读取适用的项目规则，例如根目录或上级目录中的 `AGENTS.md`、`CLAUDE.md` 及其引用文档；
2. 查找文档索引、`CONTEXT-MAP.md`、`CONTEXT.md`、现有术语表以及包含术语维护说明的文件；
3. 检查入口文件是否只是链接、指针、迁移说明或维护位置声明；如果是，继续读取其目标文件，并把目标作为唯一维护位置；
4. 扫描现有 ADR 目录，确认路径、最高编号、文件名语言、slug 风格、状态表达和章节结构；
5. 只有没有发现既有约定时，才使用本资源中的 fallback。

不要覆盖指针文件，不要因为默认模板与现有格式不同而重构已有文档，也不要创建第二份表达相同事实的术语表或 ADR。

## 术语表与上下文

### 维护原则

- 沿用目标文件已有的标题层级、语言、标点、别名标记和分组方式；例如已有文件使用 `_Avoid_` 时继续使用 `_Avoid_`，不要擅自改成其他标记。
- 沿用现有术语表的收录范围。更新既有技术术语表时，不要强行套用“只允许业务术语”的规则；新建领域术语表时，默认只记录对当前领域有特殊含义、需要统一语言的概念。
- 术语定义说明它是什么以及边界在哪里，避免把完整规格、实现步骤或临时讨论过程塞入定义。
- 同一个概念存在多个词时，选择规范术语，并按目标文件现有格式记录应避免的同义词。
- 候选术语、暂定假设和未决事项不能写成已确认事实。
- 术语与代码行为冲突时，先指出冲突并由用户决定正确规则，不要单方面让文档或代码覆盖另一方。

### 多上下文

存在 `CONTEXT-MAP.md` 或其他上下文索引时，按照索引确定术语归属和上下文关系。一个决策跨越多个上下文时：

- 术语写入负责定义它的上下文；
- 上下文之间的事件、接口或依赖关系写入现有映射或设计文档；
- 系统级决策写入仓库已有的系统级 ADR 位置。

如果存在多个合理归属且无法从代码或文档判断，把归属作为用户决策问题。

### 没有既有格式时的 fallback

仓库没有术语表约定、且用户允许创建时，单上下文可以创建：

```md
# {上下文名称}

{用一到两句话说明这个上下文的范围和存在原因。}

## 语言

**{规范术语}**：
{用一到两句话说明它是什么以及概念边界。}
_避免使用_：{容易混淆的同义词}
```

多上下文仓库可以创建根 `CONTEXT-MAP.md`，列出各上下文术语表的位置、职责以及上下文之间的关系。文件位置应基于仓库现有目录结构，不机械复制示例路径。

只有确实需要记录第一个术语时才创建文件，不创建空术语表或空上下文映射。

## ADR

### 沿用现有约定

优先沿用现有 ADR 的：

- 目录位置；
- 文件名语言和 slug 风格；
- 编号宽度及前缀；
- 状态表达方式；
- 标题、背景、决策、备选方案、影响或后果等章节结构。

扫描现有目录，取最高编号加一；编号有缺口时不要回填旧编号。创建前确认目标文件不存在，避免覆盖已有 ADR。

### 准入条件

只有以下三个条件全部满足时才创建 ADR：

1. **难以逆转**：以后改变决定的成本较高；
2. **缺少背景会令人意外**：未来读者看到实现时会追问为什么这样选择；
3. **存在真实权衡**：有实质性的替代方案，当前选择基于明确理由。

容易调整的实现偏好、显而易见的选择以及不存在真实替代方案的决定不创建 ADR。

通常值得记录的内容包括：

- 架构形态或会形成长期约束的技术选择；
- 上下文之间的集成模式；
- 数据归属、系统边界和明确的非目标；
- 有意偏离项目惯例或常见方案的选择；
- 代码中无法看出的合规、合作方或运行约束；
- 被否决但未来很可能再次提出、且否决原因不明显的替代方案。

推荐方案、暂定假设和仍未解决的权衡不能写成已接受决策。确实需要保留未确认 ADR 草案时，必须沿用项目已有状态机制明确标记为 proposed 或待确认。

### 没有既有格式时的 fallback

仓库没有 ADR 格式约定时，可以使用：

```md
# {简短的决策标题}

## 背景

{说明需要作出决定的背景和约束。}

## 决策

{说明最终选择以及选择它的理由。}

## 后果

{仅在有不明显的代价、限制或后续影响时保留本节。}
```

存在值得长期保留的被否决方案时，可以增加“考虑过的方案”章节。不要为了填满模板添加没有信息量的章节。

## 写入与结果报告

- 文档创建和修改使用正常文件工具，遵守当前工作区、权限和项目指令；本资源不提供任何额外授权。
- 写入前读取目标文件的当前内容，进行局部、幂等修改，不覆盖无关内容。
- 写入成功后报告真实修改的文件和内容范围。
- 用户未授权、权限被拒绝、目标不明确或工具不可用时，只输出拟修改位置和草案，不得声称已经创建、更新或记录。
